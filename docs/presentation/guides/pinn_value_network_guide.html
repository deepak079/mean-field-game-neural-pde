AMS 516 · Problem 21 · the task “PINN for V”, step by step

The V network: how a PINN solves the HJB

A neural network that, for an assumed final mean \(\cM{\bar m}\), learns the value \(V(t,x)\) of an investor and, from it, how much it pays to invest, \(\cP{\pi^*(t,x)}\). This guide goes from the equation to the code: where what the network must satisfy comes from, what each part of the loss measures, how it is programmed and why, and what comes out.

Colours in the formulas: each one always means the same thing

  • Timewhat changes because the clock runs: \(\partial_t\)
  • The predictable partthe interest on wealth: \(r x\)
  • Luckits cost, the curvature: \(\partial_{xx}\)
  • The decisionhow much to invest: \(\pi^*\)
  • The crowdthe assumed final mean: \(\bar m\)

The four parts of the loss have their own colour in their charts

  • Equationinside the domain
  • Final valueat \(t = T\)
  • Final slopesat \(t = T\), away from \(\bar m\)
  • Edgesat \(x = -1\) and \(x = 3\)

Where the numbers come from

The formulas and numbers in sections 2 to 5 can be redone by hand. The charts in sections 6 and 7 are what the code gives when the network is trained once with the default settings (\(\lambda = 2\), \(\bar m = 1.1\), seed 0, about 140 s on the GPU): program output, not checks.

1The map

The network solves the HJB of a single investor, with the final mean \(\bar m\) fixed. The recipe has six steps; each one is explained separately afterwards.

  1. Set up the problem of one investor To know what has to be computed: the value \(V(t,x)\) and the best investment \(\pi^*(t,x)\). §2
  2. Write the equation for \(v = \log(-V)\) To have an unknown of size 1 and nearly straight, which a network learns well. §2
  3. Fix \(v\) on three sides of the domain So that the equation has a single solution: the end \(t = T\) and the edges \(x = -1\) and \(x = 3\). §3
  4. Put a network in the place of \(v\) To look for some numbers, the weights \(\theta_V\), instead of a function. Its derivatives are exact. §4
  5. Measure with one number how much the network fails, and lower it The loss \(L_V\): one part for each thing the network must satisfy. Training is lowering it. §5§6
  6. Read \(V\) and \(\pi^*\) from the trained network That is what is delivered: today, to the charts; later, to the Fokker–Planck equation. §7

What it does not do: \(\bar m\) is an assumed number. There is no loop that corrects it, no Fokker–Planck and no comparison with finite differences; those are later tasks. The code is in src/mfg/pinn/ (branch feat/pinn-value-net) and the task summary in docs/tasks/V_PINN task/.

2The equation the network satisfies

The problem

Each investor has wealth \(X_t\) and chooses \(\cP{\pi_t}\), the dollars held in the stock. Wealth moves like this:

\[ dX_t = \big[\cB{r X_t} + \cP{\pi_t}\,(\mu - r)\big]\,dt + \cP{\pi_t}\,\sigma\,dW_t : \]

the interest on all the wealth, plus the premium on what is invested, plus the luck of what is invested. At the end, the investor wants a large mean utility,

\[ U(x,\cM{\bar m}) = -e^{-\gamma x} - \frac{\lambda}{2}\big((\cM{\bar m} - x)^+\big)^2 , \]

the usual exponential minus a penalty for ending below the mean. The value \(V(t,x)\) is the best that someone with \(x\) at time \(t\) can expect, investing well from then on:

\[ V(t,x) = \sup_{\pi}\ \mathbb{E}\big[\,U(X_T,\cM{\bar m})\ \big|\ X_t = x\,\big]. \]

Here \(\bar m\) is a fixed number: a single investor, among infinitely many, does not move the mean. The numbers are those of configs/base.yaml: \(r = 0.02\), \(\mu = 0.08\), \(\sigma = 0.2\), \(\gamma = 1\), \(\lambda = 2\), \(T = 1\), and wealth in \([-1, 3]\). Two combinations come up all the time: \(\kappa = (\mu - r)/\sigma = 0.3\), what the market pays per unit of risk, and the Merton position, \((\mu - r)/(\gamma\sigma^2) = 1.5\) dollars at \(T\), what someone without the penalty would invest.

The HJB: the best plan, from the end backwards

The idea: the best you can expect today is the best you expect after the next instant, choosing well what you invest during that instant. Itô's formula gives the mean change of \(V\) over that instant, and what remains is (full derivation in the repo notes, steps 2 to 4):

\[ \cT{V_t} + \sup_{\pi}\Big\{\big[\cB{r x} + \cP{\pi}\,(\mu - r)\big]\,V_x + \tfrac12\,\cP{\pi}^2\sigma^2\,\cR{V_{xx}}\Big\} = 0, \qquad V(T,x) = U(x,\cM{\bar m}). \]

What is inside the braces is how fast the value grows on average, per unit of time, if \(\pi\) is invested: what the drift brings minus what luck costs (\(V_{xx} \lt 0\)). The equation says that, investing as well as possible, the expected value does not change along the way: \(V\) already counts everything that can be achieved. It is known at the end, \(V(T,x) = U\), and it is solved backwards.

The best π: the top of a parabola

For fixed \(t\) and \(x\), what is inside the braces is a parabola in \(\pi\):

\[ f(\pi) = \cP{\pi}\,(\mu - r)\,V_x + \tfrac12\,\cP{\pi}^2\sigma^2\,\cR{V_{xx}} . \]

Since \(V\) is concave (\(V_{xx} \lt 0\)), it opens downwards, and its top is where its derivative is zero:

\[ \cP{\pi^*} = -\frac{\mu - r}{\sigma^2}\,\frac{V_x}{\cR{V_{xx}}} . \]

At the top, the gain is \(-(\mu - r)^2V_x^2/(\sigma^2 V_{xx})\) and the cost of luck is exactly half of it, with the opposite sign. Plugging in \(\pi^*\) leaves half the gain, and the HJB loses the sup:

\[ \cT{V_t} + \cB{r x\,V_x} - \frac{\kappa^2}{2}\,\frac{V_x^2}{\cR{V_{xx}}} = 0 . \]

This is the “reduced” HJB. It has no sup any more, but \(V_{xx}\) is left dividing: if the curvature comes out wrong, everything comes out wrong.

Why the network learns v = log(−V)

We write \(V = -e^{v}\) and the network gives \(v\). Three reasons:

  • Always well defined. \(V\) is negative, because the utility is. Written as \(-e^{v}\), it can never come out positive.
  • The same size everywhere. \(V\) goes from −7.1 (at the bottom, at \(T\)) to −0.045 (at the top, at \(t = 0\)). If the network gave \(V\), the same relative error would weigh more than 20 000 times more in the loss at the bottom than at the top, and the network would neglect the top. \(v\) goes from 1.96 to −3.11 and is nearly a straight line; without the penalty, an exact straight line in \(x\).
  • A stable π*. In the formula for \(\pi^*\), the factors \(e^{v}\) cancel.

The equation for v

With \(V = -e^{v}\), each derivative of \(V\) is \(-e^{v}\) times something simple (the last one, by the product rule):

\[ V_t = -e^{v}\,\cT{v_t}, \qquad V_x = -e^{v}\,v_x, \qquad V_{xx} = -e^{v}\big(\cR{v_{xx}} + v_x^2\big). \]

Substituting them into the reduced HJB, the last term becomes \(+\tfrac{\kappa^2}{2}\,e^{v}\,\frac{v_x^2}{v_{xx} + v_x^2}\) (the minus signs cancel). Everything carries the factor \(-e^{v}\), which is never zero; dividing by it:

The equation v satisfies, and the strategy read from it

\[ \cT{v_t} + \cB{r x\,v_x} - \frac{\kappa^2}{2}\,\frac{v_x^2}{\cR{v_{xx}} + v_x^2} = 0, \qquad \cP{\pi^*} = -\frac{\mu - r}{\sigma^2}\,\frac{v_x}{\cR{v_{xx}} + v_x^2} . \]

Two details that the code uses:

  • The denominator \(v_{xx} + v_x^2\) is \(V_{xx}/V\): positive, because \(V\) is concave and negative.
  • If \(v\) is a solution, so is \(v + 5\): its derivatives are the same. The equation alone does not choose the solution; the conditions of section 3 do.

Check by hand: without the penalty, Merton comes out

With \(\lambda = 0\) the solution is \(v = -\gamma x\,e^{r\tau} - \tfrac{\kappa^2}{2}\tau\), with \(\tau = T - t\) the time left. Its derivatives: \(v_t = \gamma r x\,e^{r\tau} + \tfrac{\kappa^2}{2}\) (\(\tau\) falls when \(t\) rises), \(v_x = -\gamma e^{r\tau}\) and \(v_{xx} = 0\). Then \(v_t + r x v_x = \tfrac{\kappa^2}{2}\), and the last term is \(\tfrac{\kappa^2}{2}\,\frac{v_x^2}{v_x^2} = \tfrac{\kappa^2}{2}\): the equation gives 0. And \(\pi^* = \frac{\mu - r}{\sigma^2}\,\frac{\gamma e^{r\tau}}{\gamma^2 e^{2r\tau}} = \frac{1.5}{\gamma}\,e^{-r\tau}\), the Merton position. It is one of the code's tests.

3What it is told on the sides

The network lives on a rectangle: time from 0 to 1 and wealth from −1 to 3. Inside, it has to satisfy the equation. On three sides it is also told what \(v\) is. At \(t = 0\) it is told nothing: the HJB is solved from the end backwards, and the value at the start is the answer, not a given.

Why is a value needed on each edge? Luck moves wealth up and down, so the equation carries information inwards from both edges. Without a value on each one there would be many solutions.

The end, t = T: the utility, exact

At \(T\) there is nothing left to decide, so \(V(T,x) = U(x, \bar m)\):

\[ v_T(x) = \log\big(-U(x,\cM{\bar m})\big) = \log\Big(e^{-\gamma x} + \frac{\lambda}{2}\big((\cM{\bar m} - x)^+\big)^2\Big). \]

This is where the penalty and \(\bar m\) come in (besides the lower edge); the equation carries them backwards. It has a kink at \(x = \bar m\), where the penalty starts. The value and the slope are continuous, but the curvature jumps: above the mean \(v_T = -\gamma x\) is a straight line (curvature 0), and just below it the curvature is \(\lambda e^{\gamma\bar m} \approx 6.0\). Since \(\pi^*\) reads the curvature, it jumps too: from 1.5 just above to 0.21 just below.

Below the mean, \(\pi^*(T,x)\) crosses the Merton line at \(x = \bar m - 1/\gamma = 0.1\), and further down it goes above it: someone already far behind takes more risk to catch up.

Top, x = 3: the Merton value

From 3, ending below 1.1 takes a fall of almost 7 standard deviations: the penalty does not reach. More precisely, the true value lies between two closed forms. Above it, the Merton value, because without the penalty one is better off. Below it, the value of holding the Merton position with the penalty (the next subsection), because playing Merton is an option, not the best one. At \(x = 3\) the two differ by about \(10^{-14}\), so this edge is exact in practice:

\[ v_{\text{high}}(t) = \log\big(-V_{\text{Merton}}(t, 3)\big) = -3\gamma\,e^{r\tau} - \frac{\kappa^2}{2}\,\tau . \]

Bottom, x = −1: the value of holding the Merton position

Here the penalty weighs a lot and there is no formula for \(V\). We use one that does exist: what someone at −1 expects if they keep the Merton position until \(T\). It is the function merton_strategy_value in benchmarks.py (PR #6), the same one the finite differences use.

The computation. Someone who keeps the Merton dollars, \(\pi_s = 1.5\,e^{-r(T-s)}\), always invests the equivalent of 1.5 dollars at \(T\). Their final wealth is normal, with mean and standard deviation

\[ M = x_{\min}\,e^{r\tau} + \frac{\kappa^2}{\gamma}\,\tau, \qquad S = \frac{\kappa}{\gamma}\sqrt{\tau} . \]

The mean of each part of the utility has a formula. The exponential gives exactly the Merton value: \(\mathbb{E}[e^{-\gamma X_T}] = e^{-\gamma M + \gamma^2 S^2/2}\). The penalty needs the mean of the squared gap, \(\mathbb{E}\big[((\bar m - X_T)^+)^2\big] = (d^2 + S^2)\,\mathrm{cdf}(d/S) + d\,S\,\mathrm{pdf}(d/S)\), with \(d = \bar m - M\), and cdf and pdf the distribution function and the density of the standard normal. Together:

\[ v_{\text{low}}(t) = \log\Big(e^{-\gamma x_{\min} e^{r\tau} - \kappa^2\tau/2} + \frac{\lambda}{2}\Big[(d^2 + S^2)\,\mathrm{cdf}\big(\tfrac{d}{S}\big) + d\,S\,\mathrm{pdf}\big(\tfrac{d}{S}\big)\Big]\Big). \]

By hand, at (t, x) = (0, −1)

\(M = -e^{0.02} + 0.09 = -0.930\), \(S = 0.3\) and \(d = 2.030\). Since \(d/S \approx 6.8\), cdf ≈ 1 and pdf ≈ 0. The exponential gives \(e^{0.930 + 0.045} = 2.652\), and the penalty, \(\tfrac{\lambda}{2}(d^2 + S^2) = 4.212\). Total: \(V = -(2.652 + 4.212) = -6.863\).

It is not the true value, but it works as a first version, for four reasons:

  • It is exact at \(T\), where no time is left, and with \(\lambda = 0\), where Merton is the best.
  • It is never above the true value: playing Merton is an option, not the best one.
  • It is very close. Near the best investment the value is flat, and straying a little only costs the square of that little. At \(x = -1\), the best at \(T\) is to invest about 2.2 instead of 1.5; the cost per unit of time is \(\tfrac12\sigma^2|V_{xx}|\,(2.2 - 1.5)^2 \approx \tfrac12\cdot 0.04\cdot 4.7\cdot 0.49 \approx 0.046\). Over a year, less than 1 % of \(|V| \approx 6.9\) (rough estimate).
  • Its small error fades inwards before it reaches where the population lives, roughly \([0, 2.2]\).

The corners

At \(t = T\), the two edges are worth exactly the final utility: \(v_{\text{low}}(T) = v_T(-1)\) and \(v_{\text{high}}(T) = v_T(3)\), because with \(\tau = 0\) there is no luck (\(S = 0\)) and \(X_T = x\). So, at the corners, the given values do not contradict each other.

4The network and its derivatives

Three different v's

From here on it helps to tell apart three things called \(v\):

\(v(t,x)\)

The exact function, \(\log(-V)\). We do not know it. Its derivatives are written with subscripts: \(v_t\), \(v_x\), \(v_{xx}\).

\(\vth(t,x)\)

The output of the network, with weights \(\theta_V\). Training is choosing \(\theta_V\) so that it resembles \(v\). Its derivatives: \(\partial_t\vth\), \(\partial_x\vth\), \(\partial_{xx}\vth\).

\(v_T,\ v_{\text{low}},\ v_{\text{high}}\)

The targets of section 3: known formulas, with no \(\theta_V\) in them.

With the trained network, \(V(t,x) \approx -e^{\vth(t,x)}\), and \(\pi^*\) is read with the formula of section 2, using the derivatives of the network.

What the network is

A function with many adjustable numbers, the weights \(\theta_V\), that takes two numbers and returns one:

\((t, x)\)→rescale to \([-1, 1]\)→4 layers of 64 tanh neurons→\(\vth(t,x)\)

Each neuron takes a weighted sum of what reaches it and applies tanh to it. In total there are 12 737 weights: 192 in the first layer, 4 160 in each of the next three and 65 in the output.

Its derivatives are exact

The network is a chain of simple operations: sums, products and tanh. PyTorch keeps that chain and applies the chain rule backwards (automatic differentiation). It gives the exact derivative of the network, not a finite-difference approximation. The second derivative comes from differentiating the first one again.

The choices, and why

tanh

It is smooth, and its second derivative is not zero. With ReLU (piecewise straight lines), \(\partial_{xx}\vth\) would be 0 almost everywhere, and the network could not draw the curvature that sets \(\pi^*\).

Inputs in [−1, 1]

\(t\) goes from 0 to 1 and \(x\) from −1 to 3. Both are brought to the same scale, where tanh is not flat.

Xavier initial weights

Random, with a size chosen so that the signal neither fades nor blows up as it crosses the layers.

4 layers × 64

\(v\) is nearly straight except in a curved zone near \((T, \bar m)\). A smaller network might not draw it, and a larger one would only cost time. It is a reasoned starting point, not a tuned one.

float32

About 7 digits of precision, plenty for \(\pi^*\) to 0.02. It is the usual choice in PyTorch, and fast on the GPU.

5The loss, part by part

Training is choosing the weights \(\theta_V\) that make one number as small as possible: the loss \(L_V\). It has four parts, one for each thing the network must satisfy. Each part is the mean of a squared error over random points:

\[ L_V(\theta_V) = \alpha_{\text{equation}}\,L_{\text{equation}} + \alpha_{\text{terminal}}\,L_{\text{terminal}} + \alpha_{\text{slopes}}\,L_{\text{slopes}} + \alpha_{\text{edges}}\,L_{\text{edges}} \]

The network does not learn from data: nobody shows it the solution. It learns from what the solution has to satisfy, and each part is a fine for breaking one of those rules. If all four were zero, the network would be the exact solution. The coefficients \(\alpha\) are 1 (why, at the end of the section).

part 1 The equation

\[ L_{\text{equation}} = \frac{1}{5000}\sum_{i=1}^{5000}\left(\frac{R_{\text{HJB}}(t_i, x_i; \theta_V)}{\kappa^2/2}\right)^2 \] \[ R_{\text{HJB}}(t,x;\theta_V) = \cT{\partial_t\vth} + \cB{r x\,\partial_x\vth} - \frac{\kappa^2}{2}\,\frac{(\partial_x\vth)^2}{\max\big(\cR{\partial_{xx}\vth} + (\partial_x\vth)^2,\ 0.05\big)} \]

What it measures. \(R_{\text{HJB}}\) is the equation for \(v\) with \(v\) replaced by the network. It is 0 where the network satisfies the equation, so \(L_{\text{equation}}\) is how much the equation fails, on average, at 5000 points inside: 4000 at random over the whole rectangle and 1000 in the box near \((T, \bar m)\).

The intuition. It is checking a solution by plugging it into the equation, but at random points, different at each step: the network cannot satisfy it at only a few places.

Why it is divided by κ²/2 = 0.045. All the terms of the equation are of that size: for Merton, for example, \(v_t + r x v_x = \kappa^2/2\) exactly. The one that carries \(\pi^*\) is the fraction. With the formula for \(\pi^*\) it can be written as \(\tfrac{\kappa^2}{2}\,(-\partial_x\vth)\,\frac{\sigma^2}{\mu - r}\,\pi^*\): about \(0.03\,\pi^*\) where \(\partial_x\vth \approx -1\). So an error of 0.1 in \(\pi^*\) would move the undivided residual by only 0.003, and it would barely show in the loss. Divided by 0.045, it moves it by 0.067: part 1 measures errors of size 1, like the others. It is the “33× trap” of guide v2 (0.03 = 1/33).

Why the max with 0.05. The fraction divides by \(\partial_{xx}\vth + (\partial_x\vth)^2\). For the exact \(v\) this is \(V_{xx}/V\), positive. But a newly created, random network can make it zero or negative at some point, and the division would blow up. The max is a safety net for the first steps: in the trained network that quantity does not drop below 0.65 anywhere (measured), far above 0.05, so it does not touch the result. \(\pi^*\) is always read without it.

part 2 The final value

\[ L_{\text{terminal}} = \frac{1}{1000}\sum_{k=1}^{1000}\big(\vth(T, x_k) - v_T(x_k)\big)^2 \]

What it measures. Whether the network has the right value at \(t = T\), at 1000 random wealths in \([-1, 3]\). The target \(v_T\) is exact.

The intuition. The equation says how \(v\) changes from one instant to the next; this part says where it starts from. Without it, \(v + 5\) would be as good as \(v\). It is also where the network learns about the penalty and \(\bar m\): changing the assumed mean is, above all, changing this target.

part 3 The final slopes

\[ L_{\text{slopes}} = \frac{1}{K}\sum_{k:\ |x_k - \bar m| > 0.05}\Big[\big(\partial_x\vth(T, x_k) - v_T'(x_k)\big)^2 + \big(\partial_{xx}\vth(T, x_k) - v_T''(x_k)\big)^2\Big] \]

What it measures. Whether the slope and the curvature of the network at \(t = T\) are those of the target. It uses the points of part 2, except those closer than 0.05 to \(\bar m\); \(K\) is how many are left, about 975. The targets are the exact derivatives of \(v_T = \log(-U)\),

\[ v_T' = \frac{U_x}{U}, \qquad v_T'' = \frac{U_{xx}}{U} - \Big(\frac{U_x}{U}\Big)^2 , \]

which above the mean are \(-\gamma\) and 0.

Why it is needed: the curvature trap. \(\pi^*\) is read from the curvature, and part 2 only looks at values. A small wiggle, such as \(0.001\sin(20\pi x)\), moves the value by a thousandth: its square, a millionth, gets lost in the loss. But its curvature reaches \(0.001\,(20\pi)^2 \approx 4\), and with that \(\pi^*\) comes out absurd. The figure lets you try it.

Why not near the mean. At \(\bar m\), the exact curvature jumps from 0 to about 6.0 (section 3). A smooth network cannot make a jump, and demanding it would spoil the fit on both sides. So the points closer than 0.05 to the mean are left out, 2.5 % of the total. The value and the slope do not jump; part 2 still asks for the value at every point.

part 4 The edges

\[ L_{\text{edges}} = \frac{1}{400}\sum_{j=1}^{200}\Big[\big(\vth(t_j, x_{\min}) - v_{\text{low}}(t_j)\big)^2 + \big(\vth(t_j, x_{\max}) - v_{\text{high}}(t_j)\big)^2\Big] \]

What it measures. Whether the network has the right value on the two edges, at 200 random times; each time is used at the bottom and at the top. The targets are those of section 3.

The intuition. The rectangle cuts the wealth axis, and at each cut the network has to be told what lies on the other side: what luck would bring in from outside. A few points are enough, because the edge values change slowly and smoothly with time.

The coefficients: all 1

With the division in part 1, the four parts measure errors of size 1, and none needs to weigh more. Guide v2 proposed 1 for the equation and 10 for the target: that made the 33× trap worse, because it gave even less weight to the part that watches \(\pi^*\) inside the domain. They can be changed in ValueNetSettings (coef_equation, coef_terminal, coef_slopes, coef_edges).

6The code, piece by piece

Two files. nets.py holds what any network in the project needs; hjb.py, everything about the \(V\) network. The table says what each piece does; then come the details that matter, and why.

One training step

  1. sample_batch draws new points and computes their targets.
  2. value_net_loss passes all the points through the network at once, and gets \(\vth\) and its derivatives.
  3. With that it computes the four parts and adds them up.
  4. total.backward() computes how the loss changes with each weight: automatic differentiation again, now with respect to \(\theta_V\).
  5. Adam moves the weights a little in the direction in which the loss goes down.

This is repeated 10 000 times, and then L-BFGS polishes.

The points: new at every step

The box of extra points. Near \((T, \bar m)\), \(\pi^*\) goes from 0.21 to 1.5 within a band about \(0.3\sqrt{T - t}\) wide: how far luck moves wealth in the time left. The box \([T - 0.1, T] \times [\bar m - 0.3, \bar m + 0.3]\) covers 1.5 % of the rectangle; with uniform points only, about 60 per step would land there. With the 1000 extra points, the box is about 18 times denser than the rest.

Why draw again. With fixed points, the network could satisfy the equation exactly at them and fail in between. Drawing at every step, over the training it covers the whole rectangle.

Two details. The \(x\) of the box are clipped to the domain, in case \(\bar m\) is near an edge. And the targets are computed with NumPy, with the functions of the rest of the repo (utility.py and benchmarks.py): there are no copied formulas, and the finite differences use exactly the same edges.

A single pass through the network

The four groups of points are stacked in a single column, in this order: inside, at \(T\), lower edge and upper edge. The network runs once per step, and then the groups are split with slices. On the GPU, a large pass costs almost the same as a small one: the step goes from 21 ms to 12 ms (measured), and a whole training takes about 140 s.

"t": torch.cat([t_in, torch.full_like(x_T, p.T), t_edge, t_edge]),
"x": torch.cat([x_in, x_T, torch.full_like(t_edge, p.x_min), torch.full_like(t_edge, p.x_max)]),

The derivatives come out at once for all the points:

def v_derivatives(v_fn, t, x):
    v = v_fn(t, x)
    # v_t and v_x in one pass back through the network, which is faster than two.
    v_t, v_x = torch.autograd.grad(v, (t, x), torch.ones_like(v), create_graph=True)
    return v, v_t, v_x, derivative(v_x, x)

create_graph=True keeps the chain of operations of the derivative, so that it can be differentiated again to get \(\partial_{xx}\vth\). Getting \(\partial_t\) and \(\partial_x\) in the same pass is faster than in two. derivative adds a detail: if one column does not depend on the other (for example, the slope of a function that is straight in \(x\), like the Merton \(v\) in the tests), PyTorch returns “nothing” instead of zeros, and the function turns it into zeros.

The loss in the code

t, x = batch["t"].requires_grad_(), batch["x"].requires_grad_()
v, v_t, v_x, v_xx = v_derivatives(net, t, x)
# Split the stacked points back into their groups (see sample_batch).
n_in, n_T = batch["n_inside"], batch["n_terminal"]
inside, final, edge = slice(0, n_in), slice(n_in, n_in + n_T), slice(n_in + n_T, None)

residual = residual_formula(x[inside], v_t[inside], v_x[inside], v_xx[inside], p)
equation = residual.pow(2).mean()
terminal = (v[final] - batch["v_T"]).pow(2).mean()
away = batch["away"]
slope_error = (v_x[final] - batch["v_T_x"])[away] ** 2
curvature_error = (v_xx[final] - batch["v_T_xx"])[away] ** 2
slopes = (slope_error + curvature_error).mean()
edges = (v[edge] - batch["v_edge"]).pow(2).mean()

It is section 5 as it stands. The mask away marks the points at \(T\) farther than 0.05 from the mean. The function also returns the four parts separately, to plot them. And residual_formula already gives the residual divided by \(\kappa^2/2\), with the safety max (MIN_CURVATURE = 0.05):

curvature = torch.clamp(v_xx + v_x**2, min=MIN_CURVATURE)
return (v_t + p.r * x * v_x) / (0.5 * p.kappa**2) - v_x**2 / curvature

The last term no longer carries \(\kappa^2/2\): dividing \(R_{\text{HJB}}\) by \(\kappa^2/2\) cancels it.

The training: Adam and, after it, L-BFGS

adam = torch.optim.Adam(net.parameters(), lr=s.lr_start)
gamma = (s.lr_end / s.lr_start) ** (1 / max(s.adam_steps, 1))
shrink = torch.optim.lr_scheduler.ExponentialLR(adam, gamma=gamma)
for step in range(s.adam_steps):
    total, parts = value_net_loss(net, sample_batch(p, mbar, s, device), p, s)
    adam.zero_grad()
    total.backward()
    adam.step()
    shrink.step()

Adam, 10 000 steps, with new points at each one. The step size starts at \(10^{-3}\) and falls smoothly to \(10^{-4}\): at each step it is multiplied by 0.99977 (in the code, gamma, which has nothing to do with the \(\gamma\) of the utility). Adam is robust when starting from random weights and with points that change; lowering the step at the end keeps it from bouncing around the minimum.

batch = sample_batch(p, mbar, s, device)
lbfgs = torch.optim.LBFGS(net.parameters(), max_iter=s.lbfgs_steps, history_size=50, line_search_fn="strong_wolfe")

def closure():
    lbfgs.zero_grad()
    total, _ = value_net_loss(net, batch, p, s)
    total.backward()
    return total

lbfgs.step(closure)

L-BFGS, up to 500 iterations, on a fixed draw. It estimates the curvature of the loss from its last 50 iterations and chooses how far to move with a line search; near the minimum it refines much faster than Adam. It needs a fixed draw because it compares the loss at several trials within one step, and with new points each time those trials would not be comparable.

The last measurement of the loss is made with new points, which the network has not seen: that way it does not show off on one particular draw. The fixed seed (0) makes two identical trainings give the same result, except for tiny GPU differences.

Reading the result

train_value_net returns a ValueNetSolution. Its methods take numbers or NumPy arrays and return arrays, broadcasting like t + x: one time and an array of wealths give a curve; two grids give a map. It is the interface agreed for every HJB solver (CONTRIBUTING.md), so the network and the finite differences can be compared directly.

p = Params.from_yaml("configs/base.yaml")         # lambda = 2
sol = train_value_net(p, mbar=1.1)                # about 140 s on the GPU
sol.value(t, x), sol.position(t, x)               # V and pi*, NumPy arrays
sol2 = train_value_net(p, mbar=1.4, net=sol.net)  # starts from the previous network

value gives \(-e^{\vth}\), and position gives \(\pi^*\) without the safety max. residual and concavity help to see where to trust it. Inside, the inputs are turned into PyTorch columns with requires_grad=True: even to read \(\pi^*\), the network has to be differentiated.

Warm start

With net=, training starts from an already trained network; it is copied first, so the original does not change. For a nearby \(\bar m\) the solution is very similar, and 3000 Adam steps with a smaller initial step (\(3\cdot10^{-4}\)) are enough: about 55 s, and the result agrees with starting from scratch to within 0.03 in \(\pi^*\) (measured once). It will be useful in the equilibrium loop: from one round to the next \(\bar m\) changes little, and each round can start from the network of the previous one.
